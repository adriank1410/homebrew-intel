## Confirmed fixes

1. Prefix-conflict handling bypassed Homebrew's `keg-only` and `skip_link`
   decisions and linked packages globally. Delegate to the standard installer
   after temporarily holding only the conflicting keg entries.
2. The same custom linking path failed on an already-linked keg with
   `Keg::AlreadyLinkedError`. Reusing the installer preserves its relinking,
   overwrite-backup and failure handling.
3. Ctrl-C during staging could strand previously moved files, including the
   just-moved entry before it reached the recovery list. Defer SIGINT during
   each move/registration and restoration, and restore on exceptional exits.
4. Local Ruby recipes can attach both `build` and `test` tags to one dependency.
   Native inspection kept only `build`, unlike API metadata that splits the
   tags. This could classify LLVM required by a formula test as disposable.
   Preserve both roles; the regression uses the real `wasi-libc` recipe.
5. Pin PR maintenance checked the changed filename but allowed unrelated policy
   edits inside it. Compare the policy at immutable base/head commits and permit
   only `brew_commit` and `core_commit` changes after the exact-head tests pass.
6. Qualified hold names passed validation but were compared without
   normalization, silently bypassing matching source holds. Normalize both the
   held formula and dependency names without modifying the supplied object.
7. Colored plan headers counted ANSI bytes as column width. Pad the visible
   labels before applying color.

Linking regressions now use disposable prefixes and real Homebrew linking,
including link/unlink cleanup. They replace two tests that depended on and
modified the developer's installed packages. CI runs those tests plus the local
recipe dependency-role regression against its pinned Homebrew/core pair.
